# ormat：多仓库补货 × Multi-Agent Transformer 练手项目

用一个精简版 MAT 研究“智能体出动作的顺序”在运筹问题里是否重要。代码全部在本目录，不依赖仓库里原来的 `mat/`。

## 问题设定

`envs/replenishment.py`：N=4 个仓库共享一个产能有限的供应商。

- 每步每个仓库选订货量 0–12；总订单超过产能 C 时按比例配给。
- 提前期 2 步，需求 ~ Poisson(μᵢ)，μ = (2, 4, 6, 8)，缺货即损失。
- 仓库异构：缺货惩罚 b = (2, 4, 8, 16)，持有成本都为 1。
- 回合长度 50 步，团队共享奖励 = −(持有成本 + 缺货成本)。
- `capacity_ratio` = 产能 / 平均总需求，越小越紧张，越需要协调谁多订、谁少订。

## 方法

| 名称 | 说明 |
|---|---|
| base-stock（临界比例） | 报童模型给出订到水平 Sᵢ，各仓库独立决策 |
| (s,S) 网格搜索 | 在临界比例水平附近搜索统一偏移和再订货间隔 |
| 按优先级配给的 base-stock | 总订单超产能时按 b 从高到低满足，是考虑产能的人工启发式 |
| MAT-fixed | 原版 MAT，按仓库编号依次出动作 |
| MAT-random | 每步随机顺序 |
| MAT-learned | 打分网络 + Plackett-Luce 采样学习顺序（PMAT 的核心思想），顺序也用 PPO 训练 |
| MAT-none | 不做自回归，各仓库并行出动作（MAPPO 式） |

## 运行

```bash
pip install -r ormat/requirements.txt
python -m ormat.baselines --capacity-ratio 0.85
python -m ormat.train --order-mode learned --seed 0 --capacity-ratio 0.85   # CPU 单线程约 5 分钟
python -m ormat.plot --results ormat/results_cap0.85 --capacity-ratio 0.85
```

## 初步结果（每种 3 个种子，300 次 PPO 更新（48 万环境步）后在 200 个评估回合上的平均成本，越低越好）

| 方法 | 产能 1.05 倍需求 | 产能 0.85 倍需求 |
|---|---|---|
| base-stock（临界比例） | 1144 | 2516 |
| (s,S) 网格搜索 | 1116 | 1594 |
| 按优先级配给的 base-stock | 1123 | **1272** |
| MAT-fixed | 1120 ± 10 | 1389 ± 16 |
| MAT-random | 1133 ± 9 | 1387 ± 13 |
| MAT-learned | 1133 ± 6 | **1362 ± 19** |
| MAT-none | 1129 ± 3 | 1376 ± 14 |

曲线见 `results/curves.png` 和 `results_cap0.85/curves.png`。

观察：

1. **产能宽松时顺序无关紧要**，所有方法都和 base-stock 打平，这个设定区分不了方法。
2. **产能紧张时**，所有 MAT 都远好于不考虑产能的 base-stock 和 (s,S)，学习顺序在四种 MAT 里最好，但差距只有 1–2 个标准差，需要更多种子确认。
3. 学到的顺序是**缺货惩罚最低的仓库 0 最先决策**（平均位次 0.39），惩罚高的仓库排在后面。一种解释是：重要的仓库最后决策，能看到前面所有人的订单再决定自己订多少。
4. 人工的优先级配给启发式仍然比所有 MAT 好约 7%，说明 RL 还有明显提升空间。

## 可以继续做的

- 把优先级启发式作为必须超过的基线；尝试更长训练、更大模型、价值归一化。
- 每种方法跑 5–10 个种子，做显著性检验。
- 把环境的配给规则改成“按决策顺序先到先得”，让顺序直接影响分配。
- 增加仓库数量（8、16），看顺序学习的优势是否随规模放大。
- 把同一框架换成医院病人分配。
