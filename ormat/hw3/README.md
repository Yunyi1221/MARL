# HW3 库存问题的多仓库版本

起点是 ORIE 5570 HW3 的单仓库库存问题：库存上限 40，订货固定成本 50、单价 1，持有成本 0.1，缺货损失 10，需求分布 `[0.1, 0.1, 0.2, 0.2, 0.1, 0.1, 0.1, 0.1]`（0 到 7），折扣 0.98，订货立即到货。最优策略是 (s,S) = (3,40)，`solve_single()` 复现了作业结果（V(0) = 534.71）。

这里把它扩展成两个仓库的五个版本。状态空间是 41×41，动作也是 41×41，仍然可以用值迭代精确求解，所以每个版本都有**真正的最优解**，可以拿来检验启发式和 MARL。

| 版本 | 耦合方式 | 最优 V(0,0) | 启发式 | 启发式 V(0,0) | 差距（(0,0) / 全状态平均 / 最大） |
|---|---|---|---|---|---|
| independent | 无耦合，成本相加 | 1069.42 | 各仓库独立 (3,40) | 1069.42 | 0 / 0 / 0 |
| joint_fixed | 联合订货：任一仓库订货付一次 50，每个下单仓库再付 10 | 966.17 | 各仓库独立 (3,40) | 1096.00 | 13.4% / 15.9% / 18.5% |
| supplier | 共享供应商：两仓库合计每期订货 ≤ 24 | 1268.23 | 各仓库独立 (3,40)，超额按比例截断 | 1351.73 | 6.6% / 4.1% / 7.9% |
| storage | 共享仓储：两仓库库存合计 ≤ 40 | 1310.51 | 各仓库独立 (3,40)，超额按比例截断 | 1381.70 | 5.4% / 5.9% / 10.7% |
| serial | 两级串联：零售店从中心仓调货，中心仓向外订货（下期到） | 621.79 | 零售店 (5,38) + 中心仓 (0,40)，网格搜索最优 | 648.21 | 4.3% / 6.6% / 10.9% |

（启发式的成本用解线性方程精确评估，不是模拟；"全状态平均"在 storage 版本中只统计合计库存 ≤ 40 的可达状态。）

## 最优策略长什么样

`results/policy_regions.png` 画了四个两仓库版本里，每个状态 (s₁, s₂) 下谁订货：

- **independent**：两条直线 s₁ ≤ 3、s₂ ≤ 3，就是两份 (3,40)。
- **joint_fixed**：只要有一个仓库需要补货，另一个仓库也顺便补满（区域里没有"只订一个"），而且再订货点从 3 降到 2，因为一次补两个仓库更划算，可以多等一会儿。这是经典联合补货问题里的 can-order 策略结构。
- **supplier**：两个仓库从不同时订货，而是轮流把供应商一期的 24 件全拿走，避免付两次固定成本又各自只拿到一半。
- **storage**：再订货点随另一个仓库的库存变化，另一个仓库越满，自己越早补但补得越少；只有两个都几乎空了才一起订。
- **serial**：中心仓在 (0,0) 时一次订满 40，零售店到 5 左右才调货，而且把中心仓的货一次调空。

这些结构正好对应多智能体里不同的协作模式：joint_fixed 需要"同步"，supplier 和 storage 需要"错开、谁先谁后"，serial 是上下游之间的信息传递。
